# Ripple 全栈深度重构计划

## 一、多维度批判性分析

### 从裁判角度（评分维度对照）

| 评分维度 | 当前状态 | 扣分点 | 改进方向 |
|----------|---------|--------|---------|
| AI原生性 | 搜索+LLM生成，本质是ChatGPT+搜索引擎 | 缺乏不可替代的AI能力展示 | 加入实时数据可视化、算法模拟、AI评审团可视化 |
| 创新性 | 知识图谱+多Agent讨论 | Agent讨论结果在前端不可见 | 让多Agent对话过程可视化、展示共识度 |
| 完整性 | 流程闭环但输出只有Markdown | 缺少可交付物 | 添加导出、模板保存、一键发布 |
| 用户洞察 | 定位准确（大学生KOC） | 但体验像给专业人用的工具 | 简化引导，添加新手教程 |
| 赛道适配 | 微信生态策略有 | 但只是文字建议，无互动 | 做成可操作的仪表盘 |

### 从用户角度

- 等待时间过长：radar流程搜索(10s)+图谱两轮LLM(30s)+报告生成(20s)=60s+
- 输出不可用：生成了一大段Markdown，用户无法直接复制到小红书
- 无引导：首次使用不知道该输入什么，Demo案例点击后又是漫长等待
- 结果无法保存/分享：生成的策略方案只在聊天中，刷新就没了

### 从后端架构角度

**[routes.py](ripple3/api/routes.py) - 1006行的单文件反模式：**
- `_stream_radar` / `_stream_idea` / `_stream_predict` / `_stream_create` / `_stream_distill` 五个函数各200+行
- 与 `intent.py` 中的 `dispatch_radar` / `dispatch_idea` 等存在**大量重复逻辑**
- 格式化函数 `_fmt_search` / `_fmt_news` 在两个文件中都有定义

**LLM调用链过长（predict流程为例）：**
1. `classify_intent` - 1次LLM调用
2. `search_parallel_predict` - 搜索
3. `score_viral_potential` - 1次LLM调用（chat_json）
4. `run_multi_agent_discussion` - 7个Agent并行=7次LLM调用 + 仲裁者1次
5. 最终报告生成 - 1次LLM调用
总计：**11次LLM调用**，耗时90s+，但用户只看到一个Markdown

**知识图谱过重：**
- `build_knowledge_graph` 做2轮LLM调用，每轮max_tokens=16384
- Pass1提取150-300个节点，Pass2建立300-600条关系
- 实测中大部分节点都是LLM编造的（搜索数据只有50-80条，但要求提取150-300个实体）

### 从内容生成角度

**Prompt质量问题：**
- `_stream_radar` 的system prompt包含"你正在参与腾讯PCG校园AI大赛"——这是竞赛meta信息泄露给用户
- Prompt过于冗长（400+字），指令太多导致LLM每条都不深入
- 缺少few-shot示例，输出格式不稳定
- temperature=0.6/0.8偏高，导致输出质量波动大

**内容流程断裂：**
- radar分析完后切到idea，搜索数据不复用——又搜一遍
- predict评分完后切到create，之前的策略不传入——重新生成
- 每个步骤独立，无"记忆"贯穿

### 从企业/腾讯角度

- 微信生态策略只是文字输出，没有可交互的组件
- "搜一搜"关键词布局是核心差异化，但只在Markdown里
- 视频号算法模拟（CES评分）数据不可视化，只是一个JSON

## 二、重构方案（按优先级排序）

### P0 - 必须改（直接影响评审印象）

#### 1. 知识图谱重写（前端+后端）

**后端优化 - [graph_builder.py](ripple3/engines/graph_builder.py)：**
- 将two-pass改为fast single-pass + 可选扩展模式
- 默认用 `build_graph_fast`（40-70节点），用户点击"扩展"再做Pass2
- 节点数量从150-300降到50-80（质量>数量）
- 移除不合理的要求（搜索50条数据不可能提取出300个真实实体）

**前端重写 - 用 @antv/g6 替代 react-force-graph-2d：**
- 原生中文支持，无Canvas手绘文字问题
- 内置力导向+层次布局，节点不再随机散布
- 自定义节点形状（不同type不同图标）
- 边标签、tooltip、点击高亮关联节点

#### 2. 字体与UI变形修复

- 中文字体优先级调整
- 图谱容器改为百分比高度（`aspect-ratio: 16/10`）
- HeroWelcome卖点行添加`flex-wrap`
- SearchRadar三阶段小屏竖排
- PrivateTab漏斗线absolute定位修复

#### 3. Prompt工程优化

**去除竞赛信息泄露：**
```python
# 删除这行：
# "你正在参与腾讯PCG校园AI大赛，赛题是帮KOC轻松涨粉"
# 改为面向用户的表述
```

**精简prompt结构：**
- radar prompt从400字减到200字，聚焦核心指令
- 降低temperature（0.6→0.4），提升输出稳定性
- 添加输出格式示例（few-shot），减少格式偏差

### P1 - 重要改进（显著提升体验）

#### 4. 后端架构重构

**拆分 routes.py：**
```
api/
  routes.py        -> 仅保留路由定义和请求处理
  pipelines/
    radar.py       -> _stream_radar 逻辑
    idea.py        -> _stream_idea 逻辑  
    predict.py     -> _stream_predict 逻辑
    create.py      -> _stream_create 逻辑
    distill.py     -> _stream_distill 逻辑
  helpers.py       -> _fmt_search, _fmt_news 等通用函数
```

**添加会话级搜索缓存：**
- 同一conversation_id内，搜索结果复用
- radar的结果传入后续idea/predict/create步骤
- 减少重复搜索调用（当前每步都重新搜）

#### 5. 用户工作流重设计

**引导式流程：**
- 在radar分析完成后，自动生成3-5个推荐选题按钮
- 选题评估完成后，一键跳转到"创作"步骤并携带上下文
- 添加"工作台"概念：保存当前session的所有分析结果

**数据跨步骤复用：**
```python
# 在_stream_radar中，将搜索结果存入session
await store.set_session_data(conv_id, "search_results", results)
await store.set_session_data(conv_id, "domain", domain)

# 在_stream_idea中，优先读取session中已有的搜索数据
cached_results = await store.get_session_data(conv_id, "search_results")
if cached_results:
    data = cached_results  # 跳过搜索，直接用缓存
```

#### 6. 多Agent讨论可视化

当前问题：`run_multi_agent_discussion` 通过SSE发送了agent发言，但前端没有渲染。

修复方案：
- 在`ChatMessage.tsx`中添加 AgentDiscussionPanel 组件
- 展示7位Agent的头像、发言、态度（看好/中立/谨慎）
- 仲裁者的最终裁定以卡片形式展示

#### 7. 微信生态可视化面板升级

将纯文字的微信策略转化为可交互组件：
- 搜一搜关键词热力图（用Recharts柱状图展示搜索量）
- 视频号CES算法模拟器（滑块调整各维度，实时计算CES分数）
- 公众号SEO关键词推荐表（可复制、可标记已布局）
- 30天日历视图（每天任务打卡）

### P2 - 加分项（锦上添花）

#### 8. 内容导出功能

- "一键复制到小红书"：自动格式化emoji、标签、分段
- "导出PDF报告"：用html2canvas截图 + jsPDF打包
- "保存为模板"：将成功的分析方案存入本地数据库

#### 9. 视觉与动效

- Hero页面Ripple水波纹动画
- 搜索中的雷达扫描效果（替代当前的线性进度条）
- 知识图谱节点出现动画（G6内置支持）
- 配色统一为Violet/Cyan双色系

#### 10. 性能优化

- 预缓存Demo案例的图谱数据（当前每次都重新生成）
- 图谱数据懒加载：先显示核心20节点，滚动到图谱区域再加载完整版
- LLM调用添加timeout和优雅降级
