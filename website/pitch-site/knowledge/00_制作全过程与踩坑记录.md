## 一、背景与目标

### 为什么要做

FlowGuard 项目之前有两个"网页"：

1. `flowguard/website/index.html`（v3 版 10 屏 Tailwind 页）—— 用户反馈"太丑了"
2. `flowguard/project/website/index.html`（v2 版 Jane Li 风格 12 屏页）—— 设计好但内容过时

两个旧页的核心问题：
- **弄虚作假**：写了"14 天灰测 12 用户""47 分钟节省"等 4/18 还没发生的数据
- **写了"决赛参赛作品"**：4/18 只是报名截止后第二天（4/17 截止），连入营都没公布
- **功能混装**：已实现 / 代码写了但权限没批 / 规划中 的功能混在一起
- **团队信息不全**：李洁盈（Jane Li）的港科 TIE 全奖、MoYa/BooxReader/Ponder 三段实习、小红书 8.2w 赞等亮点信息缺失
- **缺交互 demo**：纯文字+卡片，评委读起来枯燥

### 目标

做一个**给评委看的精美介绍网页**：
- 两套风格（A 极简留白 / B 暗色科技）让评委自选
- 4 个交互 Demo（聊天模拟器 / 6 维分类试玩 / 截图画廊 / MCP 在线调用）
- 严格区分 Built / Lab / Planned 三档功能状态
- 部署到阿里云 `http://118.178.242.26/` 替换旧主页

### 设计理念

**核心原则：单一数据源 + 双皮肤**

```
shared/data.js  ─── 所有文案、团队信息、功能列表
     │
     ├──► version-a-editorial/app.js  读 window.FG.* 渲染 14 屏
     └──► version-b-agent/app.js      读 window.FG.* 渲染 14 屏
```

改一次文案 → `data.js` 改一处 → 两版同步。

### 技术选型

| 选了什么 | 为什么 | 没选什么 |
|---|---|---|
| 原生 HTML/CSS/JS | 无构建、scp 即可部署、228K 总大小 | React / Vue / Tailwind（CDN 可能被墙 / 包体大） |
| CSS Variables | 一套变量系统，暗色/亮色只需切 :root | 预处理器（增加构建步骤） |
| Google Fonts CDN | Inter + JetBrains Mono 两款字体 | 本地字体（增加包体 200K+） |
| 纯 SVG 雷达图 | 无依赖、暗色自适应 | Chart.js（引入 70K+ 库） |
| HTML+CSS 渲染 mock 截图 | 暗色自适应、不需要 PNG 文件、缩放清晰 | 静态 PNG 截图（不适应暗色、需 Playwright） |

### `shared/chat-simulator.js`（333 行）

**飞书聊天模拟器核心**。暴露 `FG.ChatSim.mount(rootEl, { theme })`.

做了什么：

- 读 `FG.simScript` 脚本，按 `t` 时间戳依次触发事件

- 自动播放：用 IntersectionObserver 检测 rootEl 进入视口 30% 时自动开始

### `shared/classifier-playground.js`（206 行）

**6 维分类前端简化版**。暴露 `FG.Classifier.mount(rootEl, { theme })`.

核心 classify() 函数：
- D1（身份）：boss=1.0, vip=0.85, colleague=0.55, stranger=0.18, bot=0.05
- D2（关系）：跟 D1 联动
- D3（内容）：紧急词→0.95, 请教→0.65, 闲聊→0.1, 问号→0.45, 默认 0.3
- D4（任务关联）：拿用户输入的"当前任务"关键词跟消息做交集
- D5（时间）：今天/马上/deadline→0.9, 明天→0.55, 默认 0.3
- D6（频道）：p2p=0.85, small=0.55, large=0.2

权重：0.25/0.15/0.25/0.15/0.10/0.10（跟 `classification_engine.py` 完全一致）

输出：纯 SVG 雷达图 + 6 维分数条 + P 级判定 + 解释 + 是否触发 LLM 仲裁标识

6 个预设示例按钮：老板紧急 / 运维告警 / 同事请教 / 大群闲聊 / Bot 推送 / 陌生人请求

## 五、踩坑记录

### 坑 1：expect heredoc 里 `$(date ...)` 被 expect 解析

**现象**：部署脚本第一版在 expect heredoc 里写了 `$(date +%Y%m%d%H%M%S)`，expect 把 `$()` 当自己的变量解析，报错：

```
can't read "(date +%Y%m%d%H%M%S)": no such variable
```

**解决**：把远端要执行的 shell 命令抽成独立的 `remote_apply.sh` 文件，scp 上传后在远端 `bash /tmp/remote_apply.sh`。避免在 expect heredoc 里嵌套 bash 变量。

### 坑 2：nginx 备份文件留在 sites-enabled 导致冲突

**现象**：部署脚本备份旧配置时写了 `cp $NGINX_CONF $NGINX_CONF.bak.xxx`，但 `.bak.xxx` 文件还在 `/etc/nginx/sites-enabled/` 里，nginx 把它当有效配置加载 → `duplicate default server` 报错。

**解决**：
1. 备份到 `/root/nginx_backups/` 而不是原目录
2. 部署前扫描并移走所有 `*.bak.*` 和 `default` 文件：

```bash
for f in /etc/nginx/sites-enabled/*.bak.* /etc/nginx/sites-enabled/default; do
  mv "$f" "/root/nginx_backups/" 2>/dev/null || rm -f "$f"
done
```

### 坑 3：macOS tar 的扩展属性头

**现象**：`tar -xzf` 在 Ubuntu 上大量警告 `Ignoring unknown extended header keyword 'LIBARCHIVE.xattr.com.apple.provenance'`

**解决**：在打 tar 时加 `COPYFILE_DISABLE=1`：

```bash
COPYFILE_DISABLE=1 tar --exclude='.DS_Store' -czf ... 2>/dev/null
```

### 坑 4：MCP 前端 Demo 跨域

**现象**：从 `http://118.178.242.26/version-a-editorial/` 的 JS 调 `http://118.178.242.26/mcp/call` → 浏览器不报跨域（因为同域），但如果未来评委从 GitHub Pages 或其他域打开就会跨域。

**解决**：nginx 配置里给 `/mcp/` 加了完整 CORS header（含 OPTIONS 预检）：

```nginx
location /mcp/ {
    if ($request_method = OPTIONS) {
        add_header Access-Control-Allow-Origin '*';
        add_header Access-Control-Allow-Methods 'GET, POST, OPTIONS';
        add_header Access-Control-Allow-Headers 'Content-Type, Accept';
        return 204;
    }
    add_header Access-Control-Allow-Origin '*' always;
    proxy_pass http://127.0.0.1:8766/;
}
```

### 坑 5：B 版切换主题后 demo 颜色不跟着变

**现象**：B 版默认暗色，点切换到亮色后，聊天模拟器 / 分类器的 CSS 还是暗色变量。

**原因**：demo 的 CSS 在 `injectStyle()` 时读的是 `theme` 参数，但切换主题后不会重新注入。

**解决**：在 B 版 `app.js` 里写了 `remountDemos()` 函数，切换主题时先移除旧的 `<style>` 标签（通过 ID），再重新 `mount()` 重新注入。

### 坑 6：`scp` 多文件上传用 expect

**现象**：用一个 expect 块 scp 三个文件，密码只会被 expect 发一次。

**解决**：把三个文件放在一条 `scp` 命令里一次性上传：

```bash
spawn scp file1 file2 file3 root@host:/tmp/
```

scp 对同一 host 的多文件只问一次密码。

### 坑 7：node 不存在导致语法检查失败

**现象**：本机没有 `node` 命令，无法用 `node --check` 验证 JS 语法。

**解决**：跳过语法检查，直接用 Chrome 打开验证是否有 console error（更直观）。
