## 3. 一键部署命令

```bash
cd larkmentor/60_deploy
bash deploy_lark_mentor.sh
```

脚本会自动完成以下 7 步（约 3-5 分钟）：

### Step 0：本地 pytest 必须 100% 通过

```bash
cd 40_code/project && PYTHONPATH=. python3 -m pytest tests/ -q --ignore=tests/e2e --ignore=tests/simulator
```

失败直接 exit，拒绝部署。

### Step 1：打包源码（排除 .venv、data、.env）

```bash
tar --exclude='project/data' --exclude='project/.venv' --exclude='project/.env' \
    --exclude='**/__pycache__' -czf .larkmentor_release.tar.gz project/
```

### Step 2：SCP 上传 tarball 到服务器

```bash
scp .larkmentor_release.tar.gz root@118.178.242.26:/opt/larkmentor_release.tar.gz
```

用 expect 脚本 `_scp_lib.exp` 自动输入密码，不用手动交互。

### Step 3：服务器端解压 + 装依赖 + 写 systemd

```bash
# 解压
mkdir -p /opt/larkmentor && cd /opt/larkmentor && tar -xzf /opt/larkmentor_release.tar.gz

# 从 v4 继承 .env 和持久化数据（向后兼容）
cp /opt/flowguard_v4/project/.env project/.env

# 创建 venv + 装依赖
python3 -m venv .venv
.venv/bin/pip install -r project/requirements.txt

# 写 3 个 systemd unit
cat > /etc/systemd/system/larkmentor.service << EOF
[Service]
ExecStart=/opt/larkmentor/.venv/bin/python -u main.py
WorkingDirectory=/opt/larkmentor/project
EnvironmentFile=-/opt/larkmentor/project/.env
...
EOF
systemctl daemon-reload
```

### Step 4：冷切换（停 v4，启 LarkMentor）

```bash
systemctl stop flowguard-v4.service flowguard-v4-mcp.service flowguard-v4-dashboard.service
systemctl disable flowguard-v4.service ...

systemctl enable larkmentor.service larkmentor-dashboard.service larkmentor-mcp.service
systemctl start larkmentor-dashboard.service
systemctl start larkmentor-mcp.service
systemctl start larkmentor.service
sleep 6
systemctl is-active larkmentor.service larkmentor-dashboard.service larkmentor-mcp.service
```

### Step 5a：上传 web bundle（原子切换）

```bash
# 打包 70_website/version-c-larkmentor/
tar -czf .larkmentor_web.tar.gz -C 70_website/version-c-larkmentor .
scp .larkmentor_web.tar.gz root@118.178.242.26:/opt/larkmentor_web.tar.gz

# 服务器端原子切换
mkdir -p /var/www/larkmentor.new
tar -xzf /opt/larkmentor_web.tar.gz -C /var/www/larkmentor.new
mv /var/www/larkmentor /var/www/larkmentor.bak   # 备份旧版
mv /var/www/larkmentor.new /var/www/larkmentor    # 原子切换
```

两步 `mv` 都在同一文件系统，nginx 不会在中间状态下提供半写文件。

### Step 5b：写 nginx server 配置

```bash
cat > /etc/nginx/sites-available/larkmentor << 'NGX'
server {
    listen 80 default_server;
    root /var/www/larkmentor;
    index index.html;

    location = /          { try_files /index.html =404; }
    location /            { try_files $uri $uri/ /index.html; }

    location = /dashboard { proxy_pass http://127.0.0.1:8001/v3; }
    location /dashboard/  { proxy_pass http://127.0.0.1:8001/; }
    location /static/     { proxy_pass http://127.0.0.1:8001/static/; }
    location /api/        { proxy_pass http://127.0.0.1:8001/api/; }
    location = /health    { proxy_pass http://127.0.0.1:8001/health; }

    location = /mcp       { proxy_pass http://127.0.0.1:8767/; }
    location = /mcp/      { proxy_pass http://127.0.0.1:8767/; }
    location /mcp/        { proxy_pass http://127.0.0.1:8767/; }

    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_read_timeout 60s;

    gzip on;
    gzip_types text/plain text/css application/javascript application/json image/svg+xml;
    gzip_min_length 512;
}
NGX

# 切换 symlink（禁用旧的 flowguard_v4，启用 larkmentor）
rm -f /etc/nginx/sites-enabled/flowguard_v4
ln -s /etc/nginx/sites-available/larkmentor /etc/nginx/sites-enabled/larkmentor
nginx -t && systemctl reload nginx
```

## 4. nginx 配置的关键细节

### 4.1 精确匹配 vs 前缀匹配

nginx location 优先级：`=`（精确）> `^~`（前缀无正则）> `~`（正则）> 无前缀

- `location = /dashboard` → 精确匹配 `/dashboard`（不含尾斜线）
- `location /dashboard/` → 前缀匹配（含尾斜线及子路径）
- `location = /mcp` → 精确匹配 `/mcp`（不含尾斜线）

这样 `/dashboard`、`/dashboard/api` 等都能被正确处理。

### 4.2 proxy_pass 路径 strip

`proxy_pass http://127.0.0.1:8767/;`（带尾斜线）会 strip location 前缀：

```
公网请求 GET /mcp/tools
location /mcp/ 匹配
proxy_pass 后，后端收到 GET /tools
```

所以后端 `do_GET` 里只需处理 `/tools`，不需要处理 `/mcp/tools`（但加了兜底：`self.path.startswith("/mcp/tools")` 也匹配，防御性编程）。

### 4.3 gzip 对 HTML 默认开启

nginx 的 `gzip on` 对 `text/html` **默认生效**（不需要写进 gzip_types）。所以 `/mcp` 返回的 12KB HTML 会被 gzip 压缩，**curl 不加 `--compressed` 就会拿到乱码**。这是一个踩了的坑（详见 `05_踩坑记录`）。

## 5. 快速推送单文件更新

不需要每次改代码都走完整部署流程。改了某个文件后可以单独 scp：

```bash
# 更新主页 JS
SCP="larkmentor/60_deploy/_scp_lib.exp"
"$SCP" "larkmentor/70_website/version-c-larkmentor/app.js" "/var/www/larkmentor/app.js"

# 更新 Dashboard
"$SCP" "larkmentor/40_code/project/dashboard/static/dashboard_v3.html" \
       "/var/www/larkmentor/dashboard_v3.html"

# 上传 PDF
"$SCP" "larkmentor_report.pdf" "/var/www/larkmentor/larkmentor_report.pdf"
```

静态文件更新后 nginx 立即生效（无需重启）。
