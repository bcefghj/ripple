## 坑 1：nginx gzip 导致 smoke 断言失败（最坑）

**现象**

第一次部署，smoke_test 21/22，只差一条：

```
❌ MCP visual is v-c new missing 'lm-mcp-version'
```

但 `/mcp` 返回 HTTP 200，其他 20 条全过，`/mcp/tools` 里的工具名也存在。

**排查过程**

- 本地 `python3 -c "from core.mcp_server.server import _render_visual_html; html=_render_visual_html(); print('lm-mcp-version' in html)"` → `True`，说明 Python 代码没问题
- 看 smoke 里 `check_contains` 函数：`curl -sS -m 10 "$url"` 下载 body，然后 `grep -q "$needle"`
- 对比：`curl http://118.178.242.26/mcp` 直接执行，拿到乱码（二进制流）

**根因**

nginx 对 `text/html` 类型**默认开启 gzip**，不需要把 `text/html` 写进 `gzip_types`。`/mcp` 返回的 HTML 有 12.6KB，超过 `gzip_min_length 512`，所以被 gzip 压缩。

curl 不带 `--compressed` 时，响应头有 `Content-Encoding: gzip` 但 curl 不解压，`grep` 在压缩后的二进制流里当然找不到明文字符串。

**修复**

```bash
# smoke_test.sh 里所有 check_contains 加 --compressed
body=$(curl -sS --compressed -m 10 "$url" 2>/dev/null || echo "")
```

重跑，22/22 全过。

**教训**

任何用 curl 验证响应内容的脚本，都要加 `--compressed`，尤其是服务器开了 gzip 的情况。

## 坑 2：IntersectionObserver 对 JS 动态插入 DOM 无效

**现象**

hero 数字卡片、solution 卡片没有入场动画，直接显示（没有从透明飞入的效果）。

**根因**

`initReveal()` 在 `DOMContentLoaded` 时被调用，此时 DOM 里只有 index.html 里的静态元素。`renderHeroStats()`、`renderSolution()` 等函数在 `initReveal()` 之后调用，动态插入了带 `.reveal` class 的元素，但这些元素没有被 IntersectionObserver 监听到。

```js
// 有问题的顺序
document.addEventListener('DOMContentLoaded', () => {
  initReveal();        // 此时动态元素还不在 DOM 里
  renderHeroStats();   // 插入带 .reveal 的 <div>
  renderSolution();
});
```

**修复**

```js
document.addEventListener('DOMContentLoaded', () => {
  initReveal();
  renderHeroStats();
  renderSolution();
  // ... 其他 render 函数
  setTimeout(initReveal, 100);   // 再扫描一次，覆盖所有动态插入的 .reveal
});
```

另外，每个 render 函数内部也可以对自己插入的元素单独加 Observer（双重保险）。

**教训**

IntersectionObserver 观察的是"当时 DOM 里已有的元素"，动态插入的元素需要在插入后重新注册。

## 坑 3：CSS transition 需要从 0 出发

**现象**

6 维打分条从 0 动画到目标值的效果没有出现，打分条直接就是目标值，没有过渡动画。

**错误写法**

```js
// 直接设目标值，浏览器合并这次 style 修改，不触发 transition
bar.style.width = '0%';
bar.style.width = scores[i] + '%';
bar.style.transition = 'width .9s ...';
```

**根因**

浏览器会把同一个 JS 事件循环里的所有 style 修改合并成一次"强制同步布局"，从 0 到目标值没有中间帧，所以 transition 不触发。

**修复**

```js
bar.style.width = '0%';
// 强制浏览器完成一次渲染帧，再设目标值
setTimeout(() => {
  bar.style.width = scores[i] + '%';
  bar.style.transition = 'width .9s cubic-bezier(.2,.8,.3,1)';
}, 60);
```

或者用 `requestAnimationFrame(() => requestAnimationFrame(() => { ... }))`（双 rAF 更精确，60ms 是简化版）。

**教训**

CSS transition 动画必须有两个不同的 style 状态，且这两个状态必须在**不同的渲染帧**里设置。

## 坑 4：macOS tar 包含 Apple 扩展属性（LIBARCHIVE.xattr 警告）

**现象**

服务器解压 tar 包时输出大量：

```
tar: Ignoring unknown extended header keyword 'LIBARCHIVE.xattr.com.apple.provenance'
```

刷了几百行警告，视觉噪声很大。

**根因**

macOS 打的 tar 包默认包含 Apple 私有扩展属性（`com.apple.provenance` 是 macOS 14+ 新增的隔离属性，记录文件来源）。Linux 的 tar 不认识这个属性，发出警告。

已有 `COPYFILE_DISABLE=1` 环境变量，但它不能阻止 `com.apple.provenance` 被写入。

**影响**

只是警告，不影响解压结果和部署。

**可选修复**

```bash
# Linux 侧解压时加 --warning=no-unknown-keyword
tar --warning=no-unknown-keyword -xzf xxx.tar.gz
```

**教训**

macOS 打的 tar 在 Linux 上会有 xattr 警告，是已知问题，不影响功能。如果需要干净输出，在 Linux 解压命令里加 `--warning=no-unknown-keyword`。

## 坑 5：第一次部署 smoke 失败触发了自动回滚

**现象**

第一次部署 21/22（因为坑 1），smoke 失败后脚本自动执行了 rollback，把所有 LarkMentor 服务都停掉并重启了 v4。

**问题**

此时 `/var/www/larkmentor/` 里已经有新版网页了，nginx 也已经切换了，但服务被回滚到 v4（后端 v4），导致：
- 静态主页是新版 LarkMentor（正确）
- Dashboard API 又回到 v4 的响应（混乱）

**解决**

修完坑 1 后，直接重跑 `deploy_lark_mentor.sh`（幂等设计，可以重复跑），22/22 通过，一切恢复正常。

**教训**

部署脚本里的自动 rollback 机制很重要，但 rollback 只还原了服务状态，静态文件没有还原。下次可以考虑在 rollback 脚本里也把旧网页切回来（`mv /var/www/larkmentor.bak /var/www/larkmentor`）。

## 坑 6：Python 字符串拼接 HTML 里的 Unicode 字符

**现象**

MCP 可视化页的 JS 代码里，demo 参数里的中文（如 `'老板'` → `\u8001\u677f`）被 `json.dumps` 转义，看起来正常（JSON 标准）。

但在 `_render_visual_html()` 里，有一段手写的字符串直接写了中文：

```python
"'\\u738b\\u603b'"  # 这是字符串字面量里的反斜杠，不是 Unicode 转义
```

Python 字符串 `'\\u738b'` 是字面量 `\u738b`（四个字符），JSON 解析后会变成汉字。但如果写的是 `'\u738b'`（Python unicode escape），则在 Python 里就已经是汉字了，输出到 HTML 也是汉字，没问题。

**影响**

最终表现正确（中文正常显示），但代码可读性差。

**教训**

在 Python 字符串里混写 JSON 和中文时，要清楚当前层是 Python 字符串处理还是 JSON 处理。最好用 `json.dumps({"key": "中文值"}, ensure_ascii=False)` 让工具处理转义。

## 坑 7：浏览器缓存导致看到旧页面

**现象**

部署完成后，用户打开 `http://118.178.242.26/` 看到的还是旧版 FlowGuard 页面，以为部署失败。

**根因**

浏览器缓存了旧的 HTML/CSS/JS，没有请求服务器最新版本。curl 从另一台机器访问，没有缓存，看到的是新版。

**验证方法**

```bash
# 用 curl 验证服务器已经是新版
curl -sS --compressed http://118.178.242.26/ | grep '<title>'
# 输出：<title>LarkMentor · 飞书里的 AI 工作伙伴（守护注意力 + 带教新人）</title>
```

**解决方法**

- Chrome / Edge：`Cmd+Shift+R`（Mac）或 `Ctrl+Shift+R`（Windows）强制无缓存刷新
- Safari：`Cmd+Option+R` 或 Develop → Empty Caches → 刷新
- 任何浏览器：用**无痕/隐私窗口**打开，没有缓存

**后续可改进**

nginx 对 HTML 文件加 `Cache-Control: no-store` 响应头，禁止浏览器缓存：

```nginx
location = / {
    try_files /index.html =404;
    add_header Cache-Control "no-store, no-cache, must-revalidate";
}
```

或者对静态资源加版本号：`app.js?v=20260419` → 改版本号后浏览器会重新下载。
